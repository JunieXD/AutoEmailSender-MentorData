# 安全设计与威胁模型

## 信任边界

以下内容全部不可信：

- Issue 标题、正文、表单字段和标签建议；
- 上传文件、文件名、压缩包和工作表；
- URL、重定向、DNS 结果和网页内容；
- 学校、学院、姓名、邮箱、论文标题；
- 投稿者自报的账号信息；
- 第三方 Action 和依赖更新。

## Actions 注入防护

- 不在 `run:` 中插值 Issue 标题或正文。
- Python 程序只从 `GITHUB_EVENT_PATH` 读取 webhook JSON。
- 分支名、路径和临时文件名仅由经过类型校验的 Issue 编号和系统 ID生成。
- 禁止 `eval`、动态 Shell、模板执行和用户控制的命令参数。
- 机构目录使用注册表 ID，不使用用户输入路径。
- Actions 固定到完整 commit SHA，并使用最小权限。
- 不使用 `pull_request_target` 执行贡献者分支代码。

## 上传文件

- 默认最大下载 5 MiB、最多 5,000 行、每单元格最多 10,000 字符。
- XLSX 必须为普通 OOXML，不接受宏文件。
- 限制 ZIP 条目数、单条解压大小、总解压大小和压缩比。
- 拒绝公式、外部链接、数据连接、嵌入对象和路径穿越条目。
- CSV 只接受 UTF-8/UTF-8 BOM。
- 解析作业只读；写仓库作业只消费重新校验后的规范 JSON。
- 原始上传文件不提交到 Git。
- Issue Form 使用普通文本框接收 GitHub 自动生成的附件链接；不存在可执行的上传控件。
- 初始链接必须严格匹配 `github.com/user-attachments/...`，且只能有一个 CSV/XLSX 附件。
- 下载不携带 GitHub Token，只跟随有限次数的 HTTPS 重定向，并把每个目标限制在 GitHub 控制的精确域名白名单中。

## URL 与 SSRF

第一版校验只解析 URL，不主动抓取任意投稿 URL。允许的自动来源必须属于机构注册表中的已批准 HTTPS 域名。

未来若增加来源检查，必须：

- 拒绝用户名密码、非 HTTP(S) 协议和异常端口；
- 拒绝 loopback、私网、链路本地、组播和云元数据地址；
- 每次重定向重新解析 DNS 和目标 IP；
- 限制重定向次数、响应大小、内容类型和超时；
- 不携带 GitHub Token、Cookie 或用户凭据。

## 数据输出

- JSON 使用标准编码器，不拼接字符串。
- HTML 显示全部转义并启用严格 CSP。
- CSV/XLSX 导出对 `= + - @` 前缀进行公式转义。
- 构建器拒绝重复 ID、悬空引用、多个主要邮箱/任职和无来源字段。
- Manifest 包含每个分片 SHA-256 和字节数。

## 并发与发布

写入工作流使用仓库级 concurrency group，避免两个投稿同时覆盖索引。发布数据使用不可变版本目录，只有完整构建和校验成功后才生成 `latest.json`。每个已发布版本同时归档在 `gh-pages` 分支，后续 Pages 部署会带上全部旧版本，不会只保留最新目录。
