# 社区导师库总体架构

## 1. 系统边界

本项目不运行自有服务器。GitHub 负责身份、Issue、代码审查、自动化和静态文件托管；Auto Email Sender 的本地后端负责下载、校验、缓存、预览和写入用户自己的数据库。

```text
GitHub Issue
  -> 只读安全解析与账号检查
  -> 按原始学校 / 学院 / 系所组合聚合
  -> Pages 审核助手生成结构化评论
  -> 默认分支可信 Action 应用机构决策
  -> 贡献声明 Claim / 纠错提案
  -> Draft PR 或自动合并 PR
  -> 规范导师实体 + 机构注册表
  -> 不可变数据集版本
  -> GitHub Pages
  -> Auto Email Sender 本地后端
  -> 用户确认后的本地导入
```

## 2. 数据分层

### 原始投稿层

GitHub Issue 是不可变的原始投稿凭证。账号身份只从 webhook 事件的 Issue 作者读取，绝不相信正文中自报的用户名。

### 贡献声明层

每个被接受的 Issue 生成一条或多条 Claim。Claim 保存投稿者数字 ID、原始值、审核后值、字段证据和账号年龄策略结果。Claim 可以被撤销、替代或部分采用。

### 规范实体层

导师实体代表自然人，使用随机稳定 `mentor_id`。机构实体代表学校、学院、系所、研究院、实验室或中心，使用稳定 `organization_id` 和树形 `parent_id`。

邮箱、任职、主页和姓名均不是永久主键，而是带状态、来源和时间的可变属性。

### 发布层

构建器只发布可导入的规范投影，不把原始上传文件、私人审核备注或未解决冲突放入 Pages。每次构建生成不可变版本路径，最后原子更新 `latest.json`。

## 3. 导师生命周期

导师实体状态：

```text
active -> retired / departed / deceased / stale / disputed / removed
```

- `retired`、`departed`、`deceased` 和 `removed` 默认不进入学院的可导入分片。
- `stale` 和 `disputed` 保留在目录统计和撤销信息中，但不可自动导入。
- 状态变化不删除历史 Claim。
- 导师从一个机构离职并加入另一个机构时，关闭旧 affiliation，新增当前 affiliation，保持同一 `mentor_id`。

## 4. 多邮箱与多任职

导师可有多个 Contact：

```text
current / former / shared / generic / reassigned
```

只有 `current` 且非共享、非通用的邮箱可以成为默认导入邮箱。多个当前邮箱时必须明确 `is_primary`；无法确定时进入人工选择。

导师可有多个 Affiliation：

```text
current / former
```

双聘允许多个当前 Affiliation，但必须且只能有一个 `is_primary=true` 作为默认投影。软件以后可提供备选任职选择；v1 默认导入主要任职。

## 5. 去重与冲突

自动关联同一导师需要强身份信号和无矛盾保护：

- 相同规范化个人邮箱，并且姓名与机构不冲突；或
- 相同已验证高校官网导师详情页，并且姓名不冲突；或
- 已有人工裁决明确把新邮箱、旧邮箱关联到同一 `mentor_id`。

以下情况永不自动合并：

- 通用或多人共享邮箱；
- 相同邮箱但姓名或机构严重矛盾；
- 仅姓名相同；
- 同名同校但邮箱和主页均不同；
- 邮箱标记为 `reassigned`；
- 机构匹配存在歧义。

重复投稿不会增加导师实体，只增加独立 Claim 和字段来源。系统不按多数投票决定冲突值。

## 6. 自动合并资格

账号年龄只是资格门槛。自动合并还必须同时满足：

- GitHub 数字 ID 未被封禁；
- 用户类型为普通 User；
- 账号年龄达到策略阈值；
- Schema、长度、URL 和安全检查全部通过；
- 机构和来源域名已经登记；
- 没有身份或字段冲突；
- 不涉及状态删除、新机构、机构别名、纠错或撤销。

任意不满足均转入 Draft PR 或保持 Issue 待处理，不写入当前数据集。

## 7. Auto Email Sender 集成

软件不调用 GitHub API下载数据，只读取 Pages 静态文件。GitHub API 仅由 Actions 在投稿时查询账号元数据。

本地导入采用三方比较：

```text
上次导入快照 vs 当前本地数据 vs 最新社区数据
```

默认策略是新增导师并补全本地空字段，不覆盖本地非空字段、标签、个人备注、任务、发送记录或匹配结果。
